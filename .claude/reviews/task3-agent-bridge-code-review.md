### MEDIUM

1. **Timeout is per-socket-read, not a wall-clock deadline**
   (`agent_bridge.py`, `_call_gateway` → `timeout=self._timeout_seconds`)
   With `stream=True`, requests applies the timeout to connect + each read
   between chunks, not to the run as a whole. A slow-drip stream (one event
   every < 600 s) keeps a benchmark task alive indefinitely past the
   configured `timeout_seconds`. *Fix:* pass a monotonic deadline into
   `_consume_stream` and break with `[ERROR] timeout after Ns` when
   exceeded.

2. **In-flight tool calls silently dropped on early stream end**
   (`agent_bridge.py`, `_consume_stream`)
   `active_tools` entries are only flushed on `TOOL_CALL_END`. If the
   stream ends first (RUN_ERROR mid-tool-call, or EOF), those calls vanish
   from `tool_calls`. Informational field only — no score impact — but
   silent data loss in run records. *Fix:* after the loop, flush remaining
   `active_tools` with best-effort args parsing.

3. **Tautological assertion in multi-turn test**
   (`tests/test_agent_bridge.py`, `test_run_session_multi_turn`)
   `assert output.duration_seconds >= 0` is always true and asserts nothing
   about output merging (the comment above it claims "Output merges all
   turns"). *Fix:* assert the merged content, e.g. two assistant messages
   accumulated across the two turns.

### LOW

1. `_consume_stream` body exceeds 50 lines (~55) — flat elif dispatch over
   SSE event types sharing `texts`/`order`/`active_tools` state; splitting
   by event family would scatter that state. Acceptable as-is.
2. Parser requires exactly the `"data: "` prefix; SSE spec permits `data:`
   without a space. Intentional (gateway framing verified in Task 2 and
   pinned by the live-capture contract test) and documented in the
   docstring.
3. Only `requests.RequestException` is converted to `[ERROR]`; a
   non-requests error mid-stream (e.g. `UnicodeDecodeError` from
   `decode_unicode`) would propagate and crash the Runner. Rare — gateway
   emits UTF-8 JSON.
4. `run_session` appends `[ERROR]` transport messages into `history`, so
   error text becomes agent-visible context on subsequent turns.
   Continuation is by design, but error messages arguably shouldn't be
   replayed to the agent.
5. `benchmarks/.coverage` was generated by the ephemeral
   `uv run --with pytest-cov` run and was untracked (repo `.gitignore`
   doesn't cover it). **Removed during this review.** Consider adding
   `.coverage` to `.gitignore` alongside a future Task 4 docs pass.
